# 03 实施路线与验收

本文件描述后续实施，不表示这些改造已经完成。截至 2026-09-29，已完成的是扫描、61 项现有测试、依赖检查、源码 OCR 冒烟、离线探针、合成基线和规划文档；**01 中发现的问题仍在当前业务代码中**。

## 1. 实施原则

1. 不要求更换语言或桌面技术栈；每一阶段都保留可启动、可导入旧脚本的版本。
2. P1 先有失败回归用例再修复；结构搬迁与行为改变分开提交。
3. 保留当前未提交修改，先形成可回退源码快照；不要用 reset/checkout 覆盖现有工作。
4. 任何优化不得以丢失功能、误点增加、停止失效或资产路径损坏换取速度。
5. 真游戏性能/稳定性数据与合成测量分开记录。训练数据、精度和后台输入兼容性不以 mock 结果验收。
6. 旧的 2026-09-20 审计只作历史材料，不复用其过时行号和测试数。

## 2. 阶段安排

以下为一名熟悉 Python/Qt 的开发者串行推进、带必要测试的粗估，需在 S0 重新估算；不是承诺工期，不包含游戏数据标注、训练、等待硬件或不同游戏适配。

| 阶段 | 内容 | 粗估 | 完成门槛 |
| --- | --- | --- | --- |
| S0 | 固定工作区快照、测试门禁、可复跑基线 | 1–2 人日 | 可重现的源码/依赖/测试标识 |
| S1 | P1 正确性、生命周期和数据保护 | 8–12 人日 | F01–F06/F08/F09 的关键场景通过 |
| S2 | UI 热点、识别范围与截图冗余 | 5–8 人日 | 性能复测达标且结果不退化 |
| S3 | 运行器、设备、视觉、存储模块化 | 7–12 人日 | GUI 与 CLI 共享核心契约 |
| S4 | 真设备回归、长期稳定性与发布 | 3–5 人日 | 发布验收矩阵满足范围声明 |

合计约 24–39 人日，单人约 5–8 个工作周。首次可交付结果应是 S1 的可靠性修复版，不必等整个架构拆分结束。

依赖关系：

```text
S0 -> S1 数据/执行正确性 -> S2 可测热点 -> S3 逐模块抽离 -> S4 发布
                         \-> 模型黄金集与设备验收准备 ----------------/
```

## 3. 任务清单

### S0：让后续每一步可验证

**T00 建立基线和回归门禁**

- 输入：当前工作区，包括未跟踪的 YOLO、CLI、示例和测试。
- 操作：审阅并登记已有改动；固定 Python/依赖来源；将现有测试纳入 Windows CI。此次不自动提交或推送。
- 保留：`baseline.json`、`probes.json`、`source-smoke.txt` 和源码 SHA256。
- 修复冻结冒烟的基础可信度：将 `packaging_smoke.py` 中依赖 assert 的检查换成不会被 `optimize=1` 移除的显式判断，并注入一个必失败结果验证门禁确实返回失败。
- 新增测试目录规划可先不搬文件，避免一次变更同时修改测试路径与功能。
- 验收：源码导入、全部测试、依赖检查均可用一份说明复跑；日志中记录 OS、CPU、Python、包版本和 revision。
- 回滚：不触及用户项目、草稿、模型与素材。基线文件只追加新版本，不覆盖首次数据。

### S1：发布前正确性修复

**T01 条件类型校验与流程入口，关联 F01/F11**

- 修改入口：`validate_flow()`、`_normalize_window_task()`、condition 编辑器。
- 最小实现：先集中条件类型的参数校验；YOLO 校验 `model/target_class`，图片校验 `image`。未知类型明确拒绝。
- 增加重复节点 ID、非法端口、顶层 JSON 类型和坏 conditions 的错误消息。
- 测试：YOLO 是/否分支、普通图片与/或/非、节点启停、保存重开、真实 `_start_window_task` 前置校验。设备和推理用隔离替身，不触发实际输入。
- 验收：模型条件不再收到“必须有模板图片”；错误节点可以定位，旧图片判断不退化。
- 回滚：只回滚校验实现，不自动回写已有 JSON 版本。

**T02 图片与模型统一资产路径，关联 F03**

- 修改入口：`_export_asset_copies()`、`_sync_exported_image_paths()`、`_draft_payload()`。
- 最小实现：统一遍历 action/condition 的资产字段，导出前构建完整复制和路径重写计划；成功提交后同步内存，再保存草稿。
- 避免按列表顺序猜测节点对应关系，逐步使用稳定 task/node ID。
- 测试：`../external/game.onnx`、中文路径、判断节点引用、两模型同名、复制失败、JSON 替换失败、二次导出、退出重开。
- 验收：导出文件、内存文档、自动草稿引用同一有效模型；失败不留下半成品，也不删除既有文件。
- 回滚：保留原项目与新导出目录，两者不自动互相覆盖。

**T03 判定状态与错误码，关联 F04**

- 修改入口：`_evaluate_condition()`、`_condition_image_exists()`、`_condition_yolo_exists()` 和识别返回值。
- 先引入最小枚举/类型化异常，不一次性重写所有节点。
- 固定规则：NOT(FOUND) = false；NOT(NOT_FOUND) = true；ERROR/CANCELLED 不参与布尔取非，向任务层传播。
- 给步骤超时、任务超时、截图失败、模型失败、输入失败各自错误码；不再通过中文“超时”判断类型。
- 现有条件独立等待策略保留；短路和同帧判断作为后续显式策略，不隐式改变旧脚本行为。
- 测试：缺图、坏图、设备关闭、ADB 掉线、全程截图失败、检测未找到、取消；覆盖 AND/OR/NOT 组合。
- 验收：设备故障不会触发“目标不存在”的危险分支，日志解释真实原因。

**T04 模型协议预检，关联 F05**

- 修改入口：`YoloDetector.__init__()`、`detect()`、模型选择反馈。
- 明确第一批支持列表：已验证的单 batch、NCHW、三通道、detect 输出；支持的 dtype 和动态尺寸须逐项登记。
- 校验 ONNX 输入/输出元信息、类别表和检测结果布局；objectness/分割/姿态等不支持布局明确拒绝。不要默默把它们当成同一种 YOLO。
- 模型 manifest 记录 task、输入规格、类别、输出协议、来源/版本/哈希。没有 manifest 时只能识别确定无歧义的已支持布局。
- 测试：普通输出、NMS 输出、空结果、多类别、非法 class、NaN/Inf、FP16/动态维度、异常形状；使用合法授权的小模型做真实 ONNX 推理。
- 验收：不受支持模型在任何输入动作前失败；黄金图的类别与框和参考实现一致，在约定浮点误差内。
- 回滚：只禁用新模型支持，不把未知模型降级为未经验证的解码器。

**T05 统一 deadline 与操作前检查，关联 F02/F06**

- 修改入口：ScriptWorker 识别/动作、DailyRunner `_locate/_confirm/run`。
- 定义任务总 deadline、步骤 deadline、动作确认期限；取剩余预算最小值传入外部调用。
- 截图/推理返回后，动作提交前，重试开始前都检查取消与总时限。
- 区分可选步骤的“未出现/局部超时”和“设备/模型错误/总超时”，只有前者允许跳过。
- 测试：虚拟时钟跨预算、推理中停止、截图中停止、确认超时、次数上限、输入后不可撤销的反馈。
- 验收：停止后或截止后不再分发新点击；已经提交的外部动作如无法中断，状态不能虚报立即停止。
- 回滚：只还原代码，不恢复或重放取消时的点击。

**T06 可取消 I/O 与安全退出，关联 F02**

- ADB 封装为带取消 token 的进程执行器，采用短等待循环、剩余 timeout、终止/回收，隐藏控制台窗口。
- 截图先选择 ADB，成功路径不经过 PrintWindow；Win32 同步捕获没有可靠中断保证时用独立 helper 进程与超时协议。
- 关闭时进入 STOP_REQUESTED 状态，禁止新任务；活跃任务未结束则延后接受关闭，避免销毁正在运行的 QThread。
- GUI 不长时间阻塞等待，不调用 `QThread.terminate()` 作为常规停止手段。
- 测试：sleep 子进程、超时进程、丢连接、窗口捕获挂起替身、停止连续点击、退出后子进程/句柄泄漏。
- 验收：可取消等待/ADB 调用停止 p95 < 1 秒作为候选目标；不可撤销手势的边界单独披露。关窗后没有残存的自建进程，也没有 QThread 析构警告。
- 回滚：出现不确定设备状态时禁用该后端并要求用户确认，不退回全局鼠标点击。

**T07 草稿提交确认与备份，关联 F08**

- 短期：检查 QSettings status；坏草稿先保留原始内容和时间戳，再让用户选择恢复/创建空项目；增加上一有效快照。
- 长期迁移放到 S3，S1 不同时引入数据库和新文件格式。
- 测试：设置写入失败、损坏 draft、缺字段、版本不支持、断电式中断、同项目两实例写入。
- 验收：保存失败不会显示成功；坏草稿不被无提示删除；恢复可导出原文用于排查。
- 回滚：原 QSettings 数据有备份，迁移失败可继续旧读取路径。

**T08 目标实例与设备互斥，关联 F09/F10**

- GUI 复用目标解析服务；匹配多个窗口时明确失败或要求选择具体实例，不静默取第一个。
- 设备键采用解析后的 serial 或进程/窗口实例身份；任务不能直接把显示名称当互斥键。
- 同设备任务排队/拒绝，不同设备保持独立；全局设置并发上限但不暴露前台/后台切换。
- 能力不支持时在启动前提示 move、宏、Unicode 等限制；不做会抢占鼠标的隐式回退。
- 测试：同标题多开、同设备两任务、目标重启、窗口销毁/句柄复用、不同模拟器实例。
- 验收：每个动作日志可追到明确 device/run/node，设备 lease 在正常/失败/取消后均释放。

### S2：性能改造

**T09 先处理 UI 的确定性重复工作**

- 依赖 T00；修改模板库刷新、属性编辑事件、缩略图缓存。
- 第一提交只让非资产属性变化不触发解码；第二提交引入缓存/后台加载/增量通知。
- 验收：100 张图片时改名解码 0 次、p95 < 50 ms；中文路径、重命名、引用统计、删除保护、外部替换和取消选择全部通过。
- 500/1,000 张素材补充负载测试；更大负载需保持有界缓存，不能靠永久持有所有原图换速度。

**T10 截图和识别加速**

- 依赖 T03/T04/T05/T08；先实现单后端 CaptureService，再实现 ROI/缩放缓存，避免不同坐标版本混用。
- 一次条件评估可复用一张 Frame；同帧同模型重复类别请求复用推理结果。
- 推理线程与并发预算使用配置试验，不直接改成“线程越多越好”。
- 验收：ADB 成功路径 PrintWindow 调用 0 次；同帧条件 capture 1 次；ROI 坐标反投影准确；原始完整匹配保留回归。
- 性能目标：在已约定的真实素材集上识别阶段 p95 相比优化前下降至少 30%，且误点率不增加。没有真模型前，此项不得标为完成。

**T11 画布与日志增量化**

- 依赖事件结构稳定后推进；先相邻边索引，再节点增量更新，再考虑绘制模式。
- 日志采用定时批处理、有界队列和持久化；显示的轮次、错误统计来自结构化字段。
- 验收：500 节点拖动/缩放/滚动没有残影、崩溃或选择失效；100 条日志/秒持续 10 分钟时主界面仍可停止任务。给出真实 GUI 延迟测量，不能以 offscreen 方法耗时替代。

### S3：逐步拆出稳定模块

**T12 先抽纯函数，再抽基础设施**

- 第一批：默认值/校验/迁移/模型类型，配合 T01/T03/T04；保留 `app.py` 旧符号 re-export 作为过渡。
- 第二批：模板、OCR、YOLO 与路径解析/资产导出；移出后旧入口委托新模块，结果保持一致。
- 第三批：Win32/ADB 设备与输入捕获、取消/限时/设备 lease。
- 第四批：纯 runner 与 Qt bridge；最后拆页面/控制器/inspector。
- 每次搬迁单独提交，不同时改节点数据格式、UI 风格和执行语义。
- 验收：领域层/执行层导入不初始化 GUI；headless 单元测试可独立跑；不存在 `game_daily -> app.MainWindow` 或 UI -> ADB 的越层调用。

**T13 GUI 与日常任务共用核心**

- 把 `game_daily.py` 配置转换为同一 RunPlan；保留 `--game`、默认预演和显式 `--execute` 行为。
- 日常流程保留动作后确认、次数和总时限，不以 GUI 旧行为削弱 CLI 的保护。
- 双帧确认必须是两次有效采集，不能两次读取同一个缓存 Frame；指定 after 已在点击前存在仍拒绝确认。
- GUI 增加预演/运行配置入口，基于同一目标解析和识别结果，不再维护两套缓存/错误类型。
- 验收：相同计划在 GUI 与 CLI 中产生一致节点事件和终态；只有 UI 呈现方式不同。

**T14 项目存储和资产标识迁移**

- 在稳定 Project/Task/Asset ID 建立后，再迁移业务草稿到应用数据目录；QSettings 保留布局/偏好。
- 使用原子快照、修订号和最近备份；旧文件读取器长期保留一段兼容周期。
- 图片、模型、预览、诊断引用统一管理；只读资源与可删除素材明确区分。
- 验收：v1/v2/v3/v4 样例、新格式、任务改名、安装目录只读、导出搬机、坏草稿与回滚均通过。

### S4：发布与真实环境验收

**T15 真设备与模型矩阵**

- 用获授权的测试窗口/模拟器和离线游戏测试环境执行，不对生产账号自动试点。
- 最低矩阵：Win32 普通窗口、MuMu 单实例、多实例；可见/遮挡/最小化；100%/150%/200% DPI；主屏/副屏；旋转或分辨率改变。
- 模型矩阵：至少一个支持协议的真实检测模型与真实 OCR；记录模型哈希、类别、输入规格和原始/ONNX 对照结果。
- 精度验收由业务定义误点成本；在未批准动作区域不点击，误点要单独统计而不是只看 recall。

**T16 构建门禁与发布可追踪**

- 固定完整依赖来源/版本/哈希，输出发布清单；根目录文档只指向一个正式 spec。
- 构建正式 EXE，并从同一 EXE 运行不发送输入的诊断模式；不能只验证另一个 smoke 入口。
- 正式/冻结诊断不使用可能被移除的断言；至少一个故障注入测试证明错误模型/错误检测结果能使自检失败。
- 发布清单包含版本、commit、是否脏工作区、构建环境、依赖清单、文件 SHA256、模型协议和已验证设备范围。
- 便携 one-file 与候选 one-folder 分别测冷/热启动、体积和内存；本轮不指定后者一定更好。
- 验收：无 Python 的干净 Windows 上可打开、恢复草稿、预览素材、模板/OCR/YOLO 检测和停止关闭。日常 CLI 若不随包发布则明确写明。

## 5. 验收指标

所有时间目标先作为候选门槛，在 T00 固定测试硬件和负载后确认。业务正确性和停止边界优先于绝对耗时。

| 维度 | 候选门槛 | 测量方式 |
| --- | --- | --- |
| 输入安全 | 停止/超时之后新动作分发数为 0 | 虚拟时钟 + 设备适配器日志 |
| 目标隔离 | 同设备同时控制任务数最多 1 | 双任务并发场景 |
| UI 属性编辑 | 100 PNG 热态 p95 < 50 ms，解码 0 次 | 审计脚本扩展 + GUI 输入延迟 |
| 识别计算 | 指定真实集 p95 改善至少 30%，不增加误点 | 同帧同模型/素材对照 |
| 截图路径 | ADB 成功时不调用 PrintWindow | mock 调用计数 + 真设备 trace |
| 草稿 | 写入失败必提示；原始坏草稿可恢复 | IO 故障注入 |
| 停止 | 可取消步骤 p95 < 1 秒；已提交手势报告残余边界 | sleep/ADB/长推理/手势矩阵 |
| 退出 | 不遗留自建子进程、运行线程或未释放按下状态 | 多次启停/关闭 |
| 长期运行 | 预热后固定负载 8 小时，无单调泄漏趋势 | 私有字节、线程、GDI、句柄、队列长度 |
| 性能可见性 | 采集/预处理/推理/输入/确认分别有耗时 | run/node 阶段事件 |
| 发布 | 清洁环境通过正式 EXE 自检和指定设备验收 | 固定镜像/手工矩阵 |

长期测试的内存门槛需结合模型大小设置，不能简单将所有任务的总内存与无模型基线比较。建议同负载同模型比较预热后与 8 小时后状态，并同时检查泄漏趋势和缓存上限。

## 7. 迁移与回滚清单

- 每个阶段保留源码版本、正式构建、测试报告和对应项目快照。
- 模块抽取期间保留旧导入符号，避免现有测试、CLI、打包隐藏导入同时断裂。
- 新文档格式先只读迁移预览，确认后原子保存；源文件和原草稿备份不立刻删除。
- 存储回滚先还原读取版本与备份，不把新版 JSON 静默交给旧版写入器覆盖。
- 后端切换是明确策略而非异常时的隐式动作回退；回滚不能意外恢复全局鼠标输入。
- 模型更新先检测预演，再执行有界任务；失败回退到已知模型版本，而不是重新下载未知权重。
- 历史 build/dist 可另开清理任务，但删除前逐一核对绝对路径与保留版本。本轮没有执行清理。
