# 识动 VisionFlow

识动 VisionFlow 是一个基于 PySide6 的可视化桌面自动化工具。用户可以通过流程图编排窗口任务，并执行鼠标、键盘、图片识别和 OCR 操作。界面采用深色工作台风格，项目内置 `assets\fonts\NotoSansSC-VF.ttf` 中文字体资源，启动时会优先注册，避免目标机器字体回退导致中文显示为方框。

## 已支持步骤

- 单击坐标、双击坐标、移动鼠标
- 一键读取当前鼠标坐标并填入 X、Y，快捷键为 `F8`
- 按住鼠标左键拖拽，支持录制起点、终点和持续时间
- 按下按键、输入文字
- 等待时间
- 等待图片出现
- 查找图片并点击
- 窗口内等待图片、窗口内识别并点击（Win32 `PrintWindow`，支持尝试在最小化窗口中识别）
- 查找已打开的 Windows 窗口，按标题关键词或进程名匹配并读取窗口外框/客户区大小
- 从当前鼠标所在显示器框选并保存模板图片
- 截取屏幕
- 录制一整组鼠标/键盘操作为宏动作，支持单次、重复和循环执行
- 选中宏动作后查看每个事件的操作、参数和间隔时间，并可直接修改间隔（秒）
- 运行日志会记录每个步骤的开始、成功和失败；图片/窗口识别超时会输出模板路径、匹配置信度和超时时间，便于排查
- 支持“OCR文字识别”和“窗口内OCR文字识别”步骤。填写目标文字后会等待匹配文本出现；目标文字留空时，检测到任意文字即可通过。识别结果、置信度和坐标会写入运行日志，使用 RapidOCR（中英文模型）。

脚本保存为 JSON 文件，图片路径可以使用相对于脚本文件的路径。“任务步骤”页面现在是当前窗口任务专属的流程图编辑器，不再维护或复制另一份全局步骤。录制宏动作可点击工具栏中的“录制动作”，也可以按 `F9` 开始或停止；录制结束后会作为一个宏动作节点插入当前任务。
宏事件表中的“间隔（秒）”表示该事件开始前等待的时间，修改后会随脚本保存并用于回放。

窗口任务只枚举桌面登记的顶层 Windows 窗口（包含已最小化窗口）。填写标题关键词（包含匹配）或进程名（可选），运行时会等待窗口出现，并在运行日志中记录外框坐标、外框宽高和客户区宽高。下拉框可以直接选择当前窗口并自动填充匹配条件。

窗口操作现在固定使用后台模式：命中目标后不会恢复或激活窗口，而是把鼠标、键盘和宏事件发送给目标窗口，即使窗口最小化也会尝试继续执行。它适用于部分普通 Win32 控件；使用 Raw Input、DirectX 或 OpenGL 输入的游戏通常不会响应，图片识别步骤也仍然需要窗口可见。旧版脚本中的前台/后台字段会自动按后台模式处理。

## 窗口任务

“窗口任务”页面用于把不同窗口的业务操作拆成相互独立的任务：

任务的“执行模式”支持“执行一次”“重复指定次数”和“持续循环”。选择重复或持续循环后可设置轮次间隔；目标窗口只在启动时查找一次，之后重复执行整张流程图。“持续循环”会一直运行到点击“停止选中”或“全部停止”。

运行日志会为每一轮输出独立的“第 N 轮开始”和“第 N 轮结束”分隔标题；结束标题会明确标记成功、失败或已停止，单次执行同样显示为第 1 轮。每次重新启动任务时会清空日志预览；批量运行多个任务时只在批次开始时清空一次。轮次结束标题后会保留空行，便于区分下一轮内容。

1. 点击“新增任务”，在任务列表中选中它。
2. 点击“刷新列表”，从已打开窗口下拉框选择目标窗口；标题关键词和进程名会自动填充，也可以手动修改。
3. 点击“编辑步骤”进入“任务步骤”页面；也可以双击预览中的某一步。顶部任务下拉框可直接切换当前正在编辑的任务。
4. 点击“运行选中”执行单个任务，或点击“全部运行”并行执行多个任务。每个任务都会在自己的 `QThread` 中重新查找目标窗口，并在列表中显示独立状态。

任务设置和流程图会随脚本 JSON 一起保存到 `window_tasks` 字段。当前格式版本为 `4`，每个任务包含 `flow.nodes` 和 `flow.edges`；`steps` 仅作为兼容旧脚本和任务预览的派生字段。打开版本 1/2 文件时会自动把线性步骤转换为“开始 -> 操作 -> 结束”的流程图，不同的旧顶层步骤则迁移成一个独立任务。后台消息输入与图片识别的限制和窗口查找相同。

## 流程图编辑器

“任务步骤”页的画布就是当前任务的执行流程。开始节点和结束节点由系统保留，操作节点执行鼠标、键盘、图片识别、宏等动作，判断节点根据图片是否出现选择不同分支。

- 在画布空白处点击鼠标右键，可在当前位置创建操作节点或图片判断节点；顶部的“操作”“判断”按钮仍可作为快捷入口。
- 直接拖动节点调整位置；点击节点后，右侧“节点属性”会显示该节点可以修改的字段。开始/结束节点没有可编辑属性。
- 直接从节点右侧的输出端口拖到另一个节点左侧的输入端口即可连线，拖动时会显示连线预览。普通节点使用“下一步”端口；判断节点上方为“是”，下方为“否”。同一个出口重新连线会替换原来的目标。
- 节点或连线可以通过右键菜单删除，编辑内容会自动保存到本地草稿；画布右键菜单和顶部的“导出 JSON”会将当前草稿导出为脚本文件。“自动排列”会按流程拓扑重新布局节点，`Ctrl`+鼠标滚轮可以缩放画布。
- 运行前会检查所有节点是否能从开始节点到达结束节点，并检查判断节点的“是/否”分支；缺少连线时会在对话框和日志中指出节点。

判断节点当前支持“与”“或”“非”逻辑，图片路径、匹配置信度和检查超时在右侧属性中设置。多个判断节点可以通过流程图连线组合出更复杂的分支和循环。

窗口任务中可以使用“窗口内等待图片”或“窗口内识别并点击”步骤。它们会截取已查找到的目标窗口客户区，而不是整张桌面；识别成功后可以继续执行点击、拖拽、按键、文字输入或宏动作。后台模式下鼠标不会移动到目标位置。`PrintWindow` 是否能得到最小化内容取决于目标程序，使用 DirectX/OpenGL 或自行绘制的程序可能返回空白图像。

点击“截取模板”后会进入全屏遮罩框选界面，使用方式类似微信截图：拖动鼠标选择区域，选区外会变暗，按“保存”写入模板。截图优先使用鼠标所在的显示器，支持 `Esc` 或右键取消；高 DPI 环境下按原始像素裁剪。若当前已选中窗口任务，默认保存目录为脚本目录下以任务名称命名的文件夹；未选中任务时使用 `screenshots` 文件夹。目录名会保留中文，并自动替换 Windows 不允许的字符。图片写入采用 PNG 内存编码再由 `pathlib` 写盘，避免部分 OpenCV 版本对中文路径支持不完整；截图路径留空时使用 `screenshot.png`。

“模板库”页面会按任务素材目录和流程节点中的真实图片路径聚合素材。列表只显示缩略图和文件名；选中素材后，右侧会显示实际文件路径、引用次数以及具体任务/节点。双击引用或点击“定位到流程”可直接打开对应任务并选中节点。删除图片前会检查引用关系：未被引用的素材需要确认后才会删除，仍被节点使用的图片会被阻止删除，避免任务出现失效路径。相对路径解析与后台执行保持一致，优先使用任务同名目录，支持中文路径。

## 打包

项目使用 `AutomationTool-small.spec` 作为精简构建入口；该配置会通过 `collect_all('rapidocr_onnxruntime')` 收集 OCR 模型、二进制和隐藏导入，同时排除未使用的 Qt QML/Quick/PDF/SVG、视频编解码、OCR 工具模块和测试模块。它保留 Qt Widgets、OpenCV、完整 NumPy 运行时（包括 `numpy.linalg`）、ONNX Runtime、RapidOCR 和中文字体。

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pyinstaller --clean --noconfirm AutomationTool-small.spec
```

构建后必须检查 `dist\AutomationTool-small.exe` 存在，并在无 Python 环境的 Windows 机器上至少验证：普通图片识别、窗口内 OCR、中文路径模板和脚本打开/导出。使用独立自检入口验证冻结包中的图片步骤、中文路径、OCR 推理和 Qt 界面初始化（报告最后须为 `PASS`）：

```powershell
$env:AUTOMATION_BUILD_SMOKE = '1'
pyinstaller --noconfirm AutomationTool-small.spec
& .\dist\AutomationTool-package-smoke.exe (Join-Path (Get-Location) 'packaging-smoke.log')
Get-Content packaging-smoke.log
$env:AUTOMATION_BUILD_SMOKE = '0'
```

自检入口不会进入正式程序。发布时可将精简版重命名为 `AutomationTool.exe`。如果目标机器已有中文字体，可以移除 spec 中的字体数据再减少约 17 MB，但不建议默认移除。
